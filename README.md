# WARDROBE INDEX

メンズの服の**系統12種**と、**配色の原則8つ**、実際に着られる**3色の組20通り**。
色を選ぶための道具として使える日本語のリファレンスです。

系統カタログと配色ラボは実写の人物写真です。配色ラボは Canvas 上で服だけを
再着色し、元写真の陰影・しわ・素材感を残します。写真にない羽織りや帽子を足した
ときだけ、形を正確に見せる手描き SVG へ切り替わります。

ビルド工程はありません。静的な HTML / CSS / JS がそのまま GitHub Pages に載ります。

## 動かす

```bash
python -m http.server 4174
```

<http://localhost:4174> を開くだけです。

## 触る前に知っておくこと

### 1. 手持ちの数え方は「3点の組」で、着方を掛けない

`closet.js` が数えるのは**上・下・足元の3点**の組み合わせです。帽子と羽織りは
同じ3点の「着方の違い」なので掛けません。3点ごとに着方を全部試して、
最も良い着方で判定します。

掛け算にしていたときは、帽子を1つ持つだけで組数が倍になり、
**「次に買う1着＝黒のキャップ、+10通り」**という無意味な助言が出ました。
着られる幅は1ミリも広がっていないのに数だけが増えたわけです。
いまは、帽子が推薦されるのは**それが落ちていた組を救うときだけ**です。
`check.js` が「帽子を足しても組の数は増えない」ことを検算しています。

### 2. `CLOSET_PARTS` の記号は URL の意味そのもの

`h/o/t/b/s` の記号でクローゼットを URL に詰めています。カクテル早見表の
`SHELF_VOCABULARY` と同じ話で、**記号を変えると配ったリンクが全部別物を
指します。** `check.js` が並びを見張っています。

### 3. 型紙を検算するパス解析は H と V を素直に扱う

`tools/check.js` の `points()` は、SVG のコマンドを見ながら現在点を追います。
最初は数値を並び順で x,y,x,y… と数えていて、値が 1 つしかない `H`（水平）と
`V`（垂直）で以降の x と y が入れ替わっていました。靴の幅が 76〜313 と
報告されて気づきました。**検算する側が壊れているのが最も危ない**ので、
ここは手を抜かないでください。検算対象のパスは `M/L/C/H/V/Z` だけで書く決まりで、
それ以外が混ざったら落ちます。

### 4. `judge()` は SWATCHES の 3 つの列しか見ていない

`judge.js` の `judge()` が読むのは `lightness` `neutral` `vivid` だけです。
色を足すときにこの 3 つを埋め忘れると、その色は**診断から黙って外れます**
（エラーにはなりません）。`tools/check.js` が見張っています。

`vivid` は「視線を止める強さ」で、明るさとは別の軸です。
ボルドーやパープルが `vivid: true` なのに差し色として咎められないのは、
`loud()` が `vivid && lightness > 35` を見ているからです。暗い色は騒ぎません。

### 5. 例外の「破る原則」は、診断の実測と一致していること

`EXCEPTIONS` の `breaks` に原則番号を書いたら、`judge()` が**その番号だけ**を
落とさなければいけません。`breaks` が空（＝通説を破る組）なら、診断は
**通らなければいけません**。ここがずれると、「原則05 を破る」と書いた札の隣で
診断が「通ります」と言う画面になります。実際に 4 件ずれていました。

`judge()` を `judge.js` に独立させてあるのは、この検算を画面なしで回すためです。
DOM に触らないので `tools/check.js` からそのまま読めます。**judge.js に
`document` を持ち込むと検算が全部止まります。**

### 6. 収録した20組は、自分の診断を通ること

`RECIPES` に載せた組を `judge()` に入れて `bad > 0` が出ると、
ページの中で主張が食い違います。**現在この矛盾は r14 の 1 件だけ**で、
これは意図的な例外です（差し色を上に置く唯一の組）。レシピ本文でその旨を明記しています。

新しく組を足したら、必ず診断に通してください。ブラウザのコンソールで:

```js
RECIPES.filter(r => judge(...r.colors.map(swatch)).bad > 0).map(r => r.id)
```

### 7. 中身を隠す指定は `html.js` の下にしか書かない

スクロールで現れる演出のため、`[data-lazy]` は `opacity: 0` から始まります。
この指定を **`.js` で囲わずに書くと、JavaScript が動かなかった環境で
ページ全体が白紙になります。** 実際に一度その状態を作りました
（5セクションすべてが `opacity: 0` のまま公開一歩手前でした）。

`app.js` の `init()` 冒頭で `html` に `js` クラスを付けています。
この 1 行と、CSS 側の `.js [data-lazy]` は対になっています。
`tools/check.js` が両方の存在を見張っています。

保険として、`observeLazy()` は 2.5 秒経っても 1 つも現れていなければ
演出をあきらめて全部表示します。IntersectionObserver は、タブが
表示されていないなどの条件で一度も発火しないことがあるためです。

### 8. 系統の id は `[a-z0-9-]`

`app.js` の `route()` がこの文字種でハッシュを引きます。
`y2k` のように数字を含む id があるため、`[a-z-]` に狭めると開けなくなります。

### 9. 羽織りは前開きの左右2枚でなければいけない

`garment.js` の `OUTERS` は、すべて身頃を**左右2枚**に割り、中心の `x=92〜108` を
開けています。一枚の板にすると、羽織りは上着より必ず大きいので**中の服を完全に
覆い隠します。** 最初にそれをやって、12系統のうち8系統が3色のうち1色を
表示できていませんでした。絵としては成立して見えるので、目視では気づけません。

`tools/check.js` が、身頃のどのパーツも中心の通り道を跨がないことを検算します
（フードだけは頭を包むので例外。`Q` を含むパスは対象外）。

### 10. 骨格の基準線は動かせない

`garment.js` の型紙はすべて次の基準線に合わせて描かれています。
どれか一本を動かすと、他の型紙と噛み合いません。

| 位置 | y | 覚えておくこと |
| --- | --- | --- |
| 頭頂 | 0 | 頭は 44 高。全身 316 に対して **7.1 頭身** |
| 顎 | 44 | |
| 首 | 44–60 | 首は **16**。頭と同じ長さの首を描いていた時期があり、顎と襟の間が空いて頭が浮きました |
| 肩線 | 60 | 肩幅は **70**（x 64–136）＝ 頭幅 32 の 2.2 倍 |
| 腰 | 128 | |
| 尻 | 158 | |
| 膝 | 228 | |
| 踝 | 300 | 脚は1本 17 幅、脚と脚の間は 12 |
| 靴底 | 316 | 靴は x 67–133。外へ広げるとがに股に見えます |

手首は股（170 前後）まで届かせます。届いていないと腕が棒に見えます。
`viewBox` は `0 -14 200 336`。上に 14 空けているのは帽子の冠のためです。

**横幅がいちばん間違えやすい場所です。** 一度 88 幅で描いていて、上着が
虫の胸部のように張り出し、頭と腰が細く見えました。原因は「頭2つ分」と
書きながら頭の**高さ**で計算していたことです。頭幅は 32 なので、肩は 70 前後。
`check.js` が、上着は片側 18、羽織りは 26、**靴は 0**（肩幅の内側）までしか
張り出せないことを検算します。靴が肩より外に出ると、それだけでがに股に見えます。

**袖は身頃と別のパスにします。** 1 本のパスに身頃と両袖を押し込むと、
身頃だけを細くできません。脚は腰から踝へ内側に絞ります。外へ膨らませると
がに股です。

描く順も固定で、**体 → 下 → 足元 → 上 → 羽織り → 帽子 → 影**。
体を先に置かないと、色面が人の形に切り抜かれただけの旗に見えます。

影は `mix-blend-mode: multiply` の一枚で、グラデーションの `id` は呼び出しごとに
変えています。使い回すと、同じ画面に複数置いたとき最初の影が全部に効きます。

### 11. 選ぶ列は `min-width: 0` を外せない

色見本は横スクロールです（`.swatches`）。親の `.lab-controls` と `.slot` から
`min-width: 0` を外すと、grid の中で内容幅まで伸びきってスクロールが消え、
**右端の色（紫・暖色＝差し色）が選べなくなります。** `body` の
`overflow-x: hidden` に隠れて、画面上は破綻して見えないので厄介です。

### 12. 着装図と診断は同じ塊に入れる

`.lab-readout` が着装図・面積の帯・診断を包んで貼り付いています。分けると、
細い画面で図から診断まで 1100px 以上離れて、色を変えた結果が確かめられません。

### 13. 原則の図は名前で結びついている
`PRINCIPLES[].demo` の文字列が `app.js` の `DEMOS` のキーです。
片方だけ直すと、図が黙って消えます。`check.js` が対応を見ています。

### 14. 配色ラボは組み合わせ画像を持たない

`recolor.js` が、12枚の実写それぞれに合わせた部位マスクを Canvas 上で合成します。
選んだ色へ色相と明度を寄せますが、写真の輝度差は残すため、しわや縫い目は消えません。
背景は写真の端から追跡した人物輪郭で除外します。

色ごとの画像ファイルは生成しません。写真12枚とマスク定義だけなので、色・帽子・
羽織りを増やしても画像枚数は増えません。実写と形が一致しない着方では
`garment.js` の SVG に戻り、存在しない服を写真へ無理に描き足さない設計です。

## 検証

```bash
node tools/check.js          # データと型紙の突き合わせ
node tools/montage.js out.svg # 12系統の着装図を1枚に並べて目で見る
```

`montage.js` は型紙を触ったときに使います。画面を開かなくても絵の破綻が分かります。

データの件数、色の妥当性、レシピと例外が実在する色と系統を指しているか、
隣接系統が実在するか、原則の図が `DEMOS` に揃っているか、型紙に線が入っているか、
羽織りが前開きか、例外の主張と診断が一致しているか、そして判定の総当たりを見ます。

帽子なし 23³ と帽子あり 23⁴ を合わせた 292,008 通りすべてで、例外なく
1 つ以上の指摘が出ることを確認しています。この総当たりは `tools/check.js` に
入っているので、コンソールに貼る必要はありません。

## 中身の話

- **面積比 70 : 25 : 5 が、この索引の背骨です。** 色そのものより先に効きます。
  `.recipe-colors` と `.lab-ratio` の flex 比が、そのままこの数字になっています。

- **「強い色」を明るさから導くのはやめました。** 最初は
  `!neutral && 35 < lightness < 75` で判定していましたが、
  それだとキャメルのコートやくすんだピンクまで「胸元の差し色」として咎められます。
  色の強さは明るさから導けないので、`vivid` を手で付けています。

- **暖色と寒色が混ざること自体は失敗ではありません。** 原則03 が言っているのは
  「色相を散らすならトーンを揃える」で、揃っていれば深緑と茶は同居します。
  彩度の列を持っていないので、色みのある色どうしの**明度の開き**を
  トーンのずれの代わりに使っています（18 を超えたら指摘）。

- **全身一色の判定は、色の反復より先に見ます。** 順番を入れ替えると、
  `t.id === s.id` に先に当たって、全身黒が「離れた2か所の反復」として褒められます。

- **隣り合う部位の同色は「反復」ではなく「融合」です。** 離れた2か所なら意図に
  見えますが、隣どうしだと境目が消えて一つの塊になります。緑のパンツに緑の靴で
  脚から足までが一本の棒になるのがこれで、最初は帽子と上にだけ書いて
  **下と足元に書き忘れていました。** 咎めるのは `vivid` な色だけです。黒や紺は
  「通し」として狙って揃える形で、茶も革の地色なので隣り合っても別の物に読まれます。

- **「おっさんぽさ」は色の間違いではなく、コントラストの不在でした。** 機構は2つで、
  どちらも単体では変な色に見えないので指摘しにくい種類のものです。
  ひとつは**明るい暖色が上下の両方を占めること**（`hue === 'warm'` で明度45〜80、
  どちらかが非無彩色）。日に焼けた革のような色が面積の大きい2箇所に来ると、
  実年齢より上に見えます。もうひとつは**暗い錨がないこと**（全身で最も暗い部位が
  明度45より上）。締まる場所がないので輪郭がぼやけます。

- **トーンを揃えるのは上下だけです。** 原則03 を3部位すべてに当てていたとき、
  淡いデニムに茶の革靴という定番を落としていました。明度差33で確かにトーンは
  違いますが、5% の差し色に大きい面と同じ基準を当てるのは原則01（面積が先）と
  矛盾します。いまは `[t, b]` の非無彩色だけを比べます。

- **服が雑に見える原因は、輪郭の中が無地なことでした。** 実際の服は
  前立て・縫い目・ヨーク・カフス・センタープレス・靴底といった線でできています。
  `DETAILS` に部位ごとの線を持たせ、面を塗った直後にその部位の線を引きます
  （あとでまとめて引くと、上に重なる服の下から縫い目が透けます）。
  1系統あたり 22〜32 本。輪郭 1.9px に対して線は 1.05px・不透明度 62% で、
  ここを太くすると縫い目が輪郭に見えます。

- **頭身は 5.5。** 最初は頭を 74 高で描いていて 4.4 頭身、つまり頭が
  大きすぎました。頭身が足りないと、何を描いても人形の絵に見えます。

- **配色を操作する画面では、着装図を描いています。** 最初は色面を人の形に切り抜いて
  いましたが、肩が矢印になり腕が白い抜けになって、服ではなく壊れたベクターに
  見えました。いまは体を先に置き、その上に下・足元・上・羽織りの順で服を重ねます。
  型紙の名前（`shirt` `jacket` `cargo` `boot` など）を組み合わせるだけなので、
  系統を足すのは `look` を1つ書くだけです。

- **他の区画は全部「本」でした。** 分類・講義・目録・仮定の採点。読み終わって
  クローゼットの前に立つと、何を着ればいいかは分かりません。カクテル早見表が
  道具として効いていたのは、**在庫から始めて次の一手を返す**「手持ちから」が
  あったからです。この索引にはそれが無く、一度も「あなたは何を持っているか」を
  訊いていませんでした。`#closet` がその対応物です。出すのは意見ではなく数で、
  「次に買う1着」は総当たりで解きます（近似は使いません。カクテル側で
  「ベース2本＋割り材3本」という近似がモクテルに 0 杯を返した前例があります）。

- **色見本は群に分けています。** 23個を平らに並べると、選ぶ側にどれが土台で
  どれが差し色なのかが伝わりません。「土台 → 茶 → 青 → 緑 → 暖色 → 紫」の順に
  読めるようにして、群ごとに一行の説明を付けています。

## 見た目の判断

デザインの指針は Lazyweb のルーティング表から、web animation と typography の
一次ソース（emilkowalski/skill、anthropics/skills frontend-design、
petekp typography）を取得して当てています。

- **クリーム色をやめました。** frontend-design が名指しする「AI のデフォルト」
  3クラスタの 1 つ目が *クリーム地 + 高コントラストのセリフ + テラコッタ* で、
  最初の配色（`#efe7d9` + 明朝 + くすんだ赤）がほぼそれでした。
  いまは灰の混じった新聞紙（`#e7e4db`）に、リソグラフの原色
  （蛍光ピンク・電気青・黄）を `mix-blend-mode: multiply` で刷り重ねています。
  重なった部分に第三の色ができるのは、実際のリソ印刷と同じ原理です。

- **書体は主題から決めています。** Bodoni はモード誌の声そのもので、
  日本語側を Zen Old Mincho で受けると、どちらも縦線が太く横線が細いので
  同じ活字に見えます。ゴシック（Zen Kaku Gothic New）は見出しに使わず、
  ラベルと本文の実務だけを担当します。3 書体で止めています。

- **和文に字間を入れていません。** 仮名も漢字ももともと正方形の中に
  設計されているので、開けると単語の切れ目が消えて読みにくくなります。
  字間を開けるのは欧文の大文字のときだけ（`+.16em` 〜 `+.5em`）で、
  逆に大きな見出しは `-.02em` 詰めています。行間は和文なので 1.85〜2.05 です。

- **動きは transform と opacity だけ。** イージングは
  `cubic-bezier(.23, 1, .32, 1)` の強い ease-out に固定しています。
  ease-in は動き出しが遅れて鈍く感じるので UI では使いません。
  押した手応えは 160ms、ホバー 200ms、面の出入り 320ms。
  カードは 40ms ずつずらし、8 枚目で頭打ちにします
  （均等に伸ばすと、下のほうが目に見えて待たされます）。

- **`scale(0)` からは動かしません。** 潰れた点から膨らむ動きは実物に見えないので、
  `scale(.98)` から始めます。ホバーは `@media (hover: hover) and (pointer: fine)`
  で囲って、触る端末で誤発火しないようにしています。

- **署名になる要素を 1 つだけ置きました。** 画面上端の進捗計が
  70 : 25 : 5 に分かれていて、読み進むと面積の大きい色から順に満ちます。
  この索引の背骨がそのまま形になっている、というだけの仕掛けです。

- **線の太さに階層を入れました。** すべてを 2px の黒枠で囲み、すべてに同じ
  4px のオフセット影を落としていたのが、いちばん「既製品」に見える原因でした
  （いわゆるネオブルータリズムの既定値です）。いまは細線＝仕切り、
  2px＝構造、3px＝いちばん外側だけ。影は表紙の貼り紙にだけ残し、
  それ以外は滲んで沈むだけの影に変えています。系統カードは枠を細線にして
  影を外し、配色カードは枠すら持たず色面そのものが境界です。

- **同じ大きさのカードが等間隔で12枚並ぶのをやめました。** 中身より先に
  「一覧」に見えてしまうので、最初の一枚だけ 2 列取って見出しにし、
  偶数番のカードをわずかに沈めて横一線に揃わないようにしています。
  逆に配色の20組は意図して均等です。あちらは一覧で見るものだからです。

- **章番号を紙に薄く刷り、断ち落としました。** 画面の外へ逃げるので、
  「一枚のページ」ではなく「大きな紙の一部」として読まれます。
  背には章題を**縦組み**で入れています。横組みだけで組むと、日本語の誌面は
  どうしても英語の雑誌の翻訳版に見えます。四隅のトンボも同じ理由です。
